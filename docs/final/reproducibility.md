# Reproducing the evaluation

Everything in [`evaluation-results.md`](evaluation-results.md) can be regenerated with the commands below. The ORL face
set is **not** in this repository or in the release ZIP, and you must obtain it yourself.

## Environment

| Item | Value used |
|---|---|
| Python | 3.13 (3.13.16) |
| OS | Linux x86-64, 2 CPU cores |
| Key packages | numpy 2.5.3, scipy 1.18.1, scikit-learn 1.9.1, opencv-python-headless 4.14.0.94, pandas 3.0.6, joblib 1.6.0 |
| Full pinned set | `backend/requirements-lock.txt` (`pip install -r requirements-lock.txt` into a fresh Python 3.13 virtualenv; `pip check` reports no conflicts) |
| Database | PostgreSQL 16 (only for the test suite and the API benchmarks; the ML evaluation does not use it) |

The results were identical (same accuracies, same confusion matrices, same liveness figures; only timings differ) in the
original development environment and in a clean virtual environment built from the lock file. Other library versions may give
slightly different numbers (for example a different OpenCV resize implementation).

## Dataset

* **Name:** AT&T Laboratories Cambridge "Database of Faces" (formerly the ORL database): 40 subjects, 10 grayscale
  images each, 92 x 112 pixels, varied lighting, expression and small head rotations, taken 1992 to 1994.
* **Citation:** F. Samaria and A. Harter, "Parameterisation of a stochastic model for human face identification",
  Proceedings of the 2nd IEEE Workshop on Applications of Computer Vision, Sarasota, Florida, December 1994.
* **Access and licence:** it is distributed for research use by its original distributor (AT&T Laboratories Cambridge, whose
  pages have moved; it is widely mirrored). **Check the current terms at the original source before use.** It is not bundled
  here because redistribution terms are not ours to grant.
* **Provenance of the copy used for these results:** a public GitHub mirror (`alyswidan/FaceRecognition`, folder
  `orl_faces/s1..s40/1..10.pgm`), not the original distributor. If you obtain ORL from elsewhere and the images differ, your
  numbers will differ.
* **No other data.** Nothing in the evaluation is real customer or webcam data. The synthetic faces used in unit tests are
  generated by code in `backend/tests/synthetic_faces.py`.

## Preparation

Place the 40 folders `s1` to `s40` (each containing `1.pgm` to `10.pgm`) in one directory, then from the repository root:

```bash
cd backend && python3.13 -m venv .venv && . .venv/bin/activate && pip install -r requirements-lock.txt && cd ..
backend/.venv/bin/python ml/experiments/prepare_orl.py --src PATH/orl_faces --out PATH/orl.npz
```

`orl.npz` contains `X` (400, 112, 92) uint8 and `y` (400,) with values 0 to 39 (subject number minus one, images in
numeric order). `prepare_orl.py` stops if any image is missing or not 92 x 112. The `*.npz` pattern is git-ignored.

## Commands

```bash
# main results (about 4 minutes on 2 cores): closed-set, spread, open-set, liveness
backend/.venv/bin/python ml/experiments/final_evaluation.py --orl PATH/orl.npz --repeats 20 --seed 0 --out ml/results/final_evaluation.json

# figure for the documentation (needs matplotlib, which is not in requirements)
python ml/experiments/plot_results.py

# Phase 3 / 4 experiments that the final run builds on (optional)
backend/.venv/bin/python ml/experiments/benchmark.py   --orl PATH/orl.npz --repeats 20 --out ml/results/orl_benchmark.json
backend/.venv/bin/python ml/experiments/feasibility.py --orl PATH/orl.npz --repeats 10 --out ml/results/feasibility.json
backend/.venv/bin/python ml/experiments/auth_policy.py  --orl PATH/orl.npz --out ml/results/auth_policy.json

# local latency benchmark: needs the API running with relaxed limits and MIN_SAMPLES_PER_USER=8, see docs/browser-testing/README.md
backend/.venv/bin/python ml/experiments/perf_local.py --orl PATH/orl.npz --out ml/results/perf_local.json
```

## Where results are

| File | Contents |
|---|---|
| `ml/results/final_evaluation.json` | Phase 7 results: per-variant metrics, confusion matrices, training accuracy, spread over seeds, dimensionality, open-set table (mean and std over 20 splits), liveness measurements |
| `ml/results/orl_benchmark.json` | Phase 3 benchmark including the PCA sweep and scatter analysis |
| `ml/results/auth_policy.json` | Phase 4 comparison of decision rules |
| `ml/results/perf_local.json` | Phase 7 local latency benchmark |
| `ml/results/README.md` | Phase 3 to 5 write-up |

## Seeds and splits

| What | Seed / setting |
|---|---|
| Headline cross-validation | `StratifiedKFold(n_splits=5, shuffle=True, random_state=0)` over all 400 images (the app's own splitter, `app.ml.evaluation.make_splits`) |
| Spread estimate | the same splitter with `random_state` 0, 1, 2, 3, 4 |
| Open-set | numpy `default_rng(seed)` with seeds 0 to 19: random 30 enrolled / 10 impostor subjects, random 6 enrolment / 4 probe images per enrolled subject, random claimed identities |
| Liveness measurement | numpy `default_rng(0)` for the noise; the first image of each subject; Haar detector from OpenCV |
| Classifier randomness | none: PCA (full SVD), LDA (SVD solver), KNN and the linear SVM are deterministic here |

## Model configuration (all fixed before the Phase 7 evaluation)

| Stage | Setting |
|---|---|
| Preprocessing | ORL image cropped to rows 10 to 101 (square 92 x 92), then the app's `crop_to_stored`: 64 x 64 `INTER_AREA`, histogram equalisation; vectors get an elliptical mask and a per-image z-score |
| PCA | full SVD, smallest component count reaching 95% explained variance, capped at N − C, raised to C − 1 if needed so LDA can produce C − 1 components (148 components on the full ORL fit) |
| LDA | scikit-learn `LinearDiscriminantAnalysis`, solver `svd`, C − 1 components (39) |
| KNN | k = min(3, smallest class size), distance-weighted, on the LDA output (the PCA+KNN baseline uses the PCA output) |
| SVM | linear, C = 1, on the LDA output |
| Distance threshold | percentile 70 of out-of-fold genuine distances to the claimed user's centroid in LDA space |
| Decision policy | predicted identity equals claimed user, classifier score at least 0.5, distance at most the threshold (`backend/app/services/auth_policy.py`) |

## Running the tests

```bash
cd backend && cp .env.example .env   # set DATABASE_URL, TEST_DATABASE_URL (database name must end in _test), JWT_SECRET, BIOMETRIC_KEY
alembic upgrade head && python -m pytest -q          # 341 tests
ruff check app tests alembic ../ml/experiments --select F,E9,B --ignore E501,B008
alembic check
cd ../frontend && npm ci && npm test && npm run lint && npm run build
# real-browser run: docs/browser-testing/README.md
```
